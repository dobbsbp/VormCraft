# SketchUp-Style Direct Modeler — Spec v0.1

## Goal
A free, fast, direct-modeling 3D app that feels like SketchUp, for commercial work, 3D printing and CAD/CAM handoff. Built by Claude Code. No parametric timeline, no constraints: you grab faces and push them.
Use our own icons and assets, and copy nothing from SketchUp.

## Tech Stack
- Language: TypeScript (strict mode)
- Rendering and picking: Three.js, for display only. The Three.js mesh is never the model.
- Model: custom half-edge structure. Faces are true polygons and can have holes (inner loops). Triangulate only for display, and tag every triangle with the ID of its source face.
- Booleans: Manifold (WebAssembly) for cutting through solids
- Later: OpenCascade (WebAssembly) for true curves and STEP export
- Desktop app: Tauri
- Tests: Vitest. The geometry core must be fully testable without any graphics.

## Core Principles
1. Every tool accepts typed input (dimensions box): type a value, press Enter.
2. Drawing tools snap to the face under the cursor and draw on that face's plane.
3. New edges drawn on a face split that face automatically.
4. Every geometry operation has automated tests before it is considered done.

## Tools (v1)
### Select
- Click to select a face or edge. Shift to add or remove. Drag a box to select several.
- Points: a click within a few pixels of where two or more lines meet (less on an edge short on screen) selects that point (the loose end of a single line is not a point; it selects the line). Selected points show as filled squares, the one under the cursor as an outline. Move, Rotate and Scale act on the selected points (with their copies where parts touch), stretching or folding the faces around them; Delete erases the lines meeting there; Entity Info shows the position. Box selection does not take points.
- Double-click a face to select it together with its bounding edges.
- Triple-click a line or face to select everything joined to it through shared corners (`Model.connectedGeometry`): faces and lines alike, a chain of loose lines included, with parts touching it; hidden lines stay unselected. Shift adds. Right-click → Select → All Connected does the same for the selection.
### Rectangle
- Click a start corner, move, click the second corner.
- While drawing, type width,length and press Enter for exact size.
- Draws on the face under the cursor, or on the ground plane. Splits the host face.
- Snapping the second corner to a point on the model off the drawing plane turns the rectangle upright, into the red/green/blue plane holding both corners (as in SketchUp). Arrow keys fix the plane instead (→ faces red, ← green, ↑ flat); press again to unlock. A rectangle drawn exactly over an opening fills it; one along an edge that already has a face on each side gets corners of its own (it touches there).
### Closing openings
- Drawing a line over an edge of an opening (a face on one side, nothing on the other, as after deleting a box's end, or a hole in a face) follows the opening's outline and, if it closes and lies flat, fills it with a face. The back of a flat surface (faces lying in the outline's plane all round, not a hole) is not an opening.
- Faces share their lines. Erasing the line between two faces in one plane (same facing) merges them; erasing any other edge erases the faces it bounds. Drawing a line where an erased edge was closes the openings it completes, plane by plane (a box's top and front both come back).
- Lines closing a loop against existing solids: edges that already have a face on each side (a box's corners) may bound the new face too; it gets its own vertices there (it touches the solids, see "touching parts") and the drawn lines become its edges. A loop over an existing face is never filled again. Each plane is tried facing both ways; free sides of existing faces decide which. Erasing such a touching line joins the flat faces on either copy (the shape drawn against the solid moves onto the solid's corners) and erases the faces at an angle along it.
### Circle
- Click the centre, move, click to set the radius, or type the radius and press Enter.
- After the centre click the Measurements box asks for the number of sides first (default 24; Polygon too): type it and press Enter (or press Enter to keep it), then type the radius and press Enter. A decimal or a length with a unit ("2.5", "10cm") is taken as the radius straight away; a click skips the question. "32s" sets the sides at any time.
- Segment count can be set (default 24). The true radius is stored for later STEP export.
- Drawn on a face, it splits the face into an outer face with a hole plus an inner circle face.
- Arrow keys fix the plane, for Circle and Polygon alike (→ faces red, ← faces green, ↑ flat; press again to unlock), before or after the centre click: how a Follow Me profile is stood upright across a path. ↓ stands it square across the last line pointed at, at any angle (a profile for a sloping path). Drawn upright through a face, it does not split it. Tools get the last line pointed at with the key (`lockAxis(lock, edgeDir)`).
### Arcs (2-Point, 3-Point, Arc, Pie)
- The drawing plane comes from the face under the first click; at the second click, if that plane does not hold the second point, a face holding both points is used instead (the face the chord crosses, else the one under the cursor), so an arc from edge to edge of a face lies on that face and splits it.
- Every arc (2-Point, 3-Point, Arc, Pie) asks for the number of sides right after its first click, as Circle does (default 12): type a whole number and press Enter, or press Enter to keep it. A click, or a decimal or length with a unit (the radius or chord length), skips the question. Then Arc and Pie: click the start or type the radius, then type the angle in degrees or click the end; 2-Point: click the end or type the chord length, then the bulge. A 3-Point arc takes a plain number as its sides at any step. "16s" sets the sides at any time.
- Arrow keys fix the plane instead (→ faces red, ← green, ↑ blue); press again to unlock. 3-Point arcs take their plane from their three points.
### Push/Pull
- Hover a face, click, drag along its normal, click to finish, or type a distance and press Enter.
- Flush push-through: if the face reaches a coplanar opposite face of the same solid, delete both faces and keep the side walls, making a through-hole.
- Non-flush push-through: if the extrusion passes through a solid whose far side is not flush, run a boolean subtraction (Manifold) so the cut follows the solid automatically. No manual Intersect Faces step is needed.
- Pushing outward from a face adds material. Pushing inward removes it.
- A face pushed level with a neighbouring face merges with it: the edges of its outline that lie flat between level faces are removed (a step pulled up to the height beside it, an inset pushed back flush). Other drawn lines stay. Ctrl keeps the edges.
- Open surfaces: pushing a bump or dent back the way it came shortens its walls (they stretch, as with Move) instead of building new walls folded back over them. Pushed exactly flush, the walls are removed and the face rejoins the surface; pushed further, the bump becomes a dent.
- Parts touching only along an edge or at a point: each part keeps its own vertices (copies at the same spot), so every part stays a proper 2-manifold solid. The boolean rebuild keeps result vertices that Manifold treats as different apart, even at the same spot. Touching parts count as one object (`connectedFaces` follows shared and coincident vertices: selection, push/pull, Follow Me); the watertight check counts them as separate shells. A push/pull next to a contact includes the touching parts, so a shared line is split where a face stops, and parts pulled into each other merge into one solid. Faces back to back (which cannot be represented) are still refused.
- A free-standing face pushed out alongside a solid it touches (drawn against the solid's edge and pushed as deep as the solid) would leave two solids pressed face to face; the new solid is joined to every closed solid it lies against (`joinPressedSolids`, using Merge Shapes' union), so no faces are left back to back inside. Solids touching only along an edge or at a point stay apart.
- Ctrl (new starting face): the new side walls stay separate faces, leaving an edge loop where the face was, instead of merging with neighbouring faces they line up with. On a closed solid, pulling out is an ordinary (boolean) pull, so whatever the new part touches is joined properly, after which the face's old outline is drawn back where it lies on a face, as if drawn by hand; pushing in is unchanged. The model has no internal faces, so unlike SketchUp the original face itself is not kept. The mode ends with the push.
### Move and Rotate
- Rotate shows a protractor in the rotation plane: a ring with ticks every 15° (longer at 45° and 90°), the 0° line and the current one, the angle turned as a thick arc, and its value in degrees beside it (`Preview.labels`). Arrow keys pick the red/green/blue axis; ↓ rotates about the last line pointed at, whatever its angle (press ↓ again to unlock).
- A typed distance of 0 (or 0,0,0) is refused: a copy there would sit exactly on the original.
- Ctrl switches copy mode (a + on the cursor): the copy follows the mouse and the original stays. It ends with the copy, as in SketchUp; typing "3x" or "/3" afterwards makes an array. Pressing Ctrl switches at once; if another key follows while it is held (Ctrl+Z…), it was a shortcut and the switch is taken back.
- Moving, rotating or scaling part of a shape (a box's top face, an edge, a corner) stretches the faces connected to it. A connected face that can no longer lie flat (the top twisted, a corner pushed sideways) folds into flat pieces along new lines, as SketchUp's auto-fold does: a four-sided face is cut along the diagonal that leaves most of it in place, else the shorter one; pieces that stay in one plane are joined back up. Only a fold that would turn a piece over onto itself, or collapse it, is refused.
### Select All
- Ctrl+A selects everything in the model (in the open group when editing one), never the page's text; the app's labels and buttons cannot be text-selected.
### Offset
- Click a face, drag inward or outward, or type a distance.
- Creates a new edge loop offset from the face boundary, splitting the face.
### Guides (Tape Measure)
- Click an edge and drag to create a parallel guide line at a typed distance.
- Click a point and drag to create a guide point.
- Guides act as snap targets for all drawing tools and can be hidden or deleted in bulk.
### Right-click menu
- Right-click (press and release without dragging; right-drag still pans) selects what is under the cursor unless it is already selected, then opens a menu for the selection. Items that do not apply are greyed out.
- Entity Info, Erase, Hide (groups and lines), Unhide All · Edit Group, Close Group, Explode, Make Group, Merge Shapes… · Select ▸ (Bounding Edges, Connected Faces, All Connected, All with Same Material, Select All, Select None) · Reverse Faces, Flip Along ▸ (Red/Green/Blue, about the selection's centre), Soften / Unsoften Edges (selected edges, or edges between selected faces), Zoom Selection.
- Entity Info panel: a group's name (editable), contents, size and paint; faces' area and paint; edges' length and smoothing.
- Entity Info shows volumes (`volumeLines` in `src/core/check/solid.ts`, `formatVolume` in `src/tools/units.ts`): each selected group (its closed solids, with those of the groups inside it) and each closed solid the selected faces belong to counts once; flat or open shapes have none. One gives "Volume"; two to five are listed by name (group names, "Solid 1"…) with "Total volume"; more give "Solids" (the count) and "Total volume". In the design's units cubed (cubic feet for feet and inches; millimetres switch to m³ from 1 m³), with thousands separators.
- Entity Info's Solid row (for a group's own geometry, or the shapes the selected faces belong to; `solidReport` / `describeSolid` in `src/core/check/solid.ts`): "Solid" (or "N solids"), "Flat (not a solid)", or what is wrong and how to fix it: not closed (with the number of open edges, and a Select open edges button that selects them, opening the group if needed), inside out (Reverse Faces turns it), solids pressed face to face (Merge Shapes joins them; this check is skipped above 2,000 faces of solids). Problems show in red.
- Reverse Faces refuses to turn a whole solid that faces outward inside out (it says why); a solid that is inside out can be turned the right way. Follow Me makes a swept shape that closes up face outward, whichever way the profile faces and the path runs.
- Safety net: development builds and the tests check every change (`ToolController.onSolidsWorse`): one that opens a solid, turns one inside out or leaves solids pressed face to face is logged in development and refused in tests. Erase and the Eraser may open solids on purpose. Off in released builds.
- Merge Shapes… (enabled for two or more shapes): `src/core/ops/mergeShapes.ts`. A selected face stands for its whole solid (touching parts each count as a solid); a selected group for its geometry. Two or more flat faces (not part of a closed solid) lying in one plane merge at once into the face(s) they cover together, facing and painted like the first, holes kept where nothing covers them. Two or more solids and/or groups ask first: Unify (a Manifold union: faces inside where they overlap or touch go, faces left in one plane merge, true circles kept; groups only → one group named after the first, its subgroups moved in; otherwise the result joins the geometry being edited) or Keep shapes (they go into one new group unchanged, as Make Group). With two or more solids/groups, flat faces selected with them (such as the circle left inside a Follow Me ring, often caught by a box selection) are left as they are, and the question and a notice say so; Keep shapes puts them in the group too. One solid plus flat faces or open surfaces is refused with a message explaining that a box drawn on a face is part of that face, not a solid. The menu item is enabled whenever two or more faces/groups are selected, so a refusal is explained in the status bar instead of the item being greyed out. One undo step.
- Not included: Lock, Make Component, Unglue, Reset Scale/Skew, Intersect Faces (no components or locking yet; booleans already cut automatically).
### Inference Snapping (applies to all tools)
- Snap to endpoints, midpoints, edges, faces, guide intersections, and the red, green and blue axes.
- Show a visual cue for the active snap.
### Follow Me
- Select the path (connected edges, or a face to follow its edge), then click the profile face. The profile is swept along the path with mitred corners. Paths need not be flat (up a slope, then along).
- One loose line selected follows every loose line joined to it end to end (as drawn with the Line tool), stopping where lines branch, and says how many; Shift when clicking the profile follows only the selected line. A tool can say something after a click (`Tool.notice`).
- A free-standing profile becomes a new solid; a closed path turns it right round (lathe). A profile drawn on a solid cuts a groove or chamfer along the path.
- Curved profiles and paths give smooth (soft-edged) surfaces, with true curves kept where the path has arcs. A straight part running on into an arc without a corner (an elbow) is smooth too; real corners show their mitres. Seams stay smooth when the sweep is cut into or joined onto a solid (a rounded edge, a groove).
- Flat parts swept from one profile edge (a dome's or cylinder's base) are one face, not a fan of wedges; walls lying in one plane round a corner merge.
- A free-standing sweep that overlaps another closed solid, or lies against it: drawn mostly inside it, it is cut out of it (a groove round a cylinder, from a profile drawn into it); otherwise it is joined on.
- A selected path face left inside the new solid or on its surface (the disc inside a sphere, under a dome or cylinder) is removed; one outside it (the disc in a ring) stays.
- A selected face's outline is kept whole as the path even where the profile shares an edge with it (a rounded edge drawn at a box's top corner follows the whole top outline); a closed path may run along a profile edge. The start is the path corner nearest the profile; of equally near corners, the one where the path runs most squarely across the profile.
- Refused, with what to do: a profile lying along the path rather than across it (flat on it, or turned more than about 75°: "press → or ← while drawing to stand it upright"); a profile bigger than a bend of the path, which would fold over itself (each profile point must go forward along each step of the path, or stay put on a lathe's axis: "Did you pick them the wrong way round?"). Hint: select the path (e.g. a big circle), then click the profile (e.g. a small circle standing upright on its edge).
- Tested shapes (`tests/followMeShapes.test.ts`, through the tool): rings (profile on, beside or outside the circle; path as a face or edges), sphere, dome, bowl, cylinder, straight pipe, elbow, mitred pipe, picture frame, rounded box edge, groove round a cylinder; each one closed solid facing outward, of the right volume, smooth where round, closed when exported, kept by saving, one undo step.
### Materials (Paint Bucket)
- Paint faces with a colour (optionally see-through) or a texture image tiled at a real-world size. Materials are saved in the document.
- Click paints a face (a whole curved surface; all selected faces if the clicked face is selected). Shift: every face with the same paint. Ctrl: connected faces with the same paint. Alt: pick up a face's paint.
- Paint follows the geometry: faces split from a painted face, and pushed or moved faces, keep their paint.
- Materials window: floats over the view (dragged by its title bar, kept on screen, place remembered as `vormcraft.materials.position`) and stays open beside the side panels. The editor for the current material (name, colour, opacity, texture image and tile size), then tabs: In model (with Default, which removes paint), Colours (our own, grouped Neutrals, Warm, Cool, See-through) and Textures (our own artwork drawn in code, grouped Wood, Stone and brick, Ground, Metal and fabric); the tab is remembered (`vormcraft.materials.tab`).
### Groups
- Select geometry and press Ctrl+G (Make Group): it moves into a group with geometry of its own, so it never sticks to or merges with anything outside it. Selected groups go inside the new group (groups can hold groups).
- A group selects, moves, rotates, scales, copies, erases and paints as one piece. Painting a group colours its faces that have no paint of their own.
- Double-click a group to edit its contents with every tool; the rest of the model is faded. Esc (with nothing selected), a click outside it, or the Close badge closes it.
- Explode Group (Search) puts a group's geometry back into the geometry around it, joining it up where it touches.
- Groups are saved in the file and included in STL and OBJ export.
### View: styles, projection, hiding
- Face styles: Textured, Shaded (colours only), Wireframe (edges only, faces not pickable), X-ray (see-through faces; edges behind them stay pickable). The toolbar has one Style button (showing the current style; opens a menu) and one Views button (showing the view it last went to; a click goes on to the next of Iso, Top, Front, Right, Back, Left, round in order; right-click lists them all), so the toolbar fits on one row from about 1300 px wide. Back edges (K) and the background colour are part of the style.
- Sky and ground (Style menu → Sky and ground…, Search): by default a sky fading from blue overhead to pale at the horizon over plain ground. Sky: Clear (gradient) or Soft clouds (drawn in code, fixed in the world so they turn with the view), with sky and horizon colours. Ground: Plain, Grass, Paving, Sand (patterns drawn in code, in millimetres, tinted by the ground colour; choosing one sets its usual colour) or None. Presets: Day, Soft clouds, Evening, Plain (off: the plain background colour, as before). The window changes the view as you choose (Cancel puts it back).
  - Drawn as one screen-filling layer before everything (`src/view/backdrop.ts`, a shader working out each pixel's view ray): it never hides, covers or catches clicks on the model; parallel views and the top and front views work. Patterns fade to their colour where they would shimmer, and the ground lightens into the horizon colour towards the distance.
  - Kept per device (localStorage `vormcraft.backdrop`, with the plain colour), not in the design. A scene saves the sky and ground with its style and shows them when gone to; scenes from before keep the view's own (`DisplayStyle.backdrop` is optional; read from the file only if valid, so the file format did not change: older versions ignore it).
- Perspective or parallel projection (toolbar). Parallel keeps the scene the same size on screen when switched on; zoom, pan and zoom window work in both.
- Hide (Ctrl+H, right-click, Search) the selected groups and lines; selected faces hide the lines between them (as Soften does). Hidden groups are not drawn, picked, snapped to or box-selected; they are still saved and exported.
- A hidden line (`hidden` on both half-edges, saved from format 7) is not drawn, picked, snapped to, box-selected or taken by Select All, but the faces either side stay separate faces (unlike a soft edge, which joins them into one smooth surface). Splitting it keeps both halves hidden; copies keep it. Hidden lines cannot stay selected after Hide.
- Show Hidden Lines (the status bar's Show button, right-click, Search; not saved, switched off once no lines are hidden) draws the hidden lines of the model being edited dashed (`buildDisplayData(..., showHidden)` puts them after `hiddenFrom`), and they can be clicked and right-clicked. Unhide (right-click, Search) shows the selected hidden lines again, as one undo step.
- Unhide All (Ctrl+Shift+H, right-click, Search) shows every hidden group and line in the whole design, as one undo step. While anything is hidden, the status bar shows how much is hidden ("2 lines, 1 group hidden"), with Show (Show Hidden Lines, when lines are hidden) and Unhide all.
### Viewer mode (touch)
- The eye button ("Viewer", next to the logo; also in Search) puts the tools away for looking at a model on a phone, foldable or tablet (or any screen): toolbar, palette, side panels and status bar are hidden; nothing can be selected or edited. Never switched on automatically. `src/app/viewerMode.ts` (UI), `Viewer.viewerMode` (input), `src/view/touchGestures.ts` (pure gesture maths, tested).
- Touch (and pen): one finger pans (the point under it follows the finger). Two fingers do two things at once: pinching zooms toward the point between them (spreading to twice the distance makes the model look twice as big) and moving them together orbits about that point. Adding or lifting a finger carries on from where the fingers are, without a jump. A flick keeps the pan or orbit gliding and slowing down (about 325 ms to 1/e); any new touch, click or wheel stops it. A double-tap centres the view on the point tapped. The user chose this mapping after testing it on people; do not switch it to one-finger orbit.
- Mouse in Viewer mode: middle-drag orbits, right-drag pans, the wheel zooms, as usual; the left button does nothing, there is no hover highlight and no right-click menu. Keys: Esc leaves Viewer mode; Page Up / Page Down step through scenes; everything else is ignored.
- A bar in the top-right corner (clear of notches): Exit viewer (large, crossed-out eye), Zoom to fit, Open, Google Drive (when shown) and a gear for the drawing resolution (Sharpest 1, Balanced 0.75, Faster 0.5, Fastest 0.35 of the screen's pixel ratio; kept on the device as `vormcraft.viewer.resolution`, used only in Viewer mode). Scene tabs move to the bottom with larger buttons. A hint with the gestures shows for a few seconds on entering. Browser gestures are kept out (touch-action none on the view, Safari's gesturestart, no pull-to-refresh).

- A scene is a saved view: camera (position, target, field of view, projection, parallel view height), hidden groups, and style (face style, back edges, guides, background). Scenes are saved in the file; adding, updating, deleting, renaming and reordering them are undo steps, going to one is not.
- Each scene has checkboxes for what it restores (camera, hidden groups, style). Going to a scene changes style and hidden groups at once and glides the camera there (ease-in-out, transition time configurable, default 1 s).
- Scenes panel: list (click to go, double-click to rename, arrows to reorder, ✕ to delete), Add scene, Update (overwrite with the current view, keeping name and place), Play/Stop, timings. Tabs along the top of the viewport go to a scene in one click; Page Up / Page Down step through them.
- Slideshow: plays the scenes in order, gliding for the transition time and staying for the delay, looping until Esc or a click.
- Not yet captured (the features do not exist yet): tags/layers, section planes, sun/shadows, fog.
### Autosave, history and settings
- Autosave every N minutes (default 1) when the design changed: records a version and writes a recovery copy (`<name>-<hash>.autosave.vorm`) to the backup folder (default: the app's local data folder; browser: IndexedDB). The design's own file is never written by autosave. The copy is removed when the design is saved or its changes discarded; copies left at startup are offered back (newest first) and deleted after N days (default 14).
- History: versions of the whole document (gzip, base64, textures stored once by hash) recorded at each autosave, save, open (if the file has none) and restore; identical states are not recorded twice. Thinned: all from the last day, newest per hour for a week, newest per day before that; trimmed to a size limit (default 25 MB). Saved in the .vorm file (format 5); a damaged history never stops the design opening.
- Looking at a version is read-only (tools, undo and redo are refused; Esc or Back to now returns). Restoring records the current design first, then replaces the document as one undo step.
- Settings (stored on the computer, kept across updates): autosave on/off and minutes, backup folder, keep-for days, history on/off and size limit, check for updates at startup.
### Undo saved with the design
- Format 6 keeps the newest 100 undo steps (at most 8 MB compressed) in the file when history is on, so Undo works after reopening. Each step is a line diff (`src/io/lineDiff.ts`) from the step after it, over the design written one record per line (`linedJson`), gzipped; a step that changed nearly everything is stored whole. Steps are rebuilt only when undone to. A hash of the design ties the steps to it: a file changed outside VormCraft opens without them. Steps already encoded are reused on the next save.
### Desktop app, updates and compatibility
- Windows installer (NSIS, per-user, no admin), built by GitHub Actions from a version tag; `.vorm` files open with a double-click. Updates: the Tauri updater reads `latest.json` from the newest GitHub Release, checks at startup (Settings) and on request, shows the CHANGELOG notes, installs and restarts. Updates are signed; the private key is a repository secret. The app identifier `app.vormcraft.modeler` must never change (settings live under it).
- Graphics: WebGL through WebView2 (Direct3D 11); asks for the high-performance GPU, warns when only a software renderer is available, redraws after a graphics driver reset. About shows the version and GPU.
- Web version on Windows: browsers ignore the page's high-performance request and Windows usually gives them the built-in GPU. On built-in graphics (classified from the WebGL renderer name; WebGPU's high-performance adapter names a faster card's maker when it differs) a dismissible tip shows once how to set the browser to High performance in Windows' graphics settings; Settings → Graphics card shows the steps too.
- Every older file format keeps opening (sample file per format version in `tests/fixtures`, tested). Files from a newer version are refused with an offer to update. The first save over an older-format file keeps a copy of the original.
### Website pages
- `public/about/`, `public/privacy/`, `public/terms/` (plain HTML, shared `public/site/site.css`, light and dark) are published with the web version at vormcraft.app/about/, /privacy/, /terms/. They are the home page, privacy policy and terms Google's OAuth verification asks for. ### Google Drive (web version and Windows app)
- `src/app/drive`: `driveApi.ts` (Drive REST v3 with fetch, `drive.file` permission only: VormCraft sees only files it created; retries 429/5xx/rate limits with backoff, new token after 401, uploads over 5 MB resumable in 8 MB pieces), `googleAuth.ts` (web sign-in through Google Identity Services; token in memory only), `desktopAuth.ts` (Windows app sign-in, below), `preview.ts` (where Drive is shown), `driveSession.ts` (account, the VormCraft folder at the top of My Drive, designs, autosaved copies in VormCraft/Autosave, clash check by head revision), `driveAutosave.ts` (upload timing), `driveCommands.ts` (menu and commands), `driveDialog.ts` (Open list).
- The design's own Drive file is written only by Save (Ctrl+S saves back to the Drive file a design was opened from or saved to). Before writing, the file's revision is compared with the one opened or last saved; if it changed elsewhere: Replace (Drive keeps the old one in its own version history) or Keep both (saved as "Name (2)").
- Autosave a copy to Google Drive (each person switches it on; off by default): one file per design in VormCraft/Autosave, replaced each time, uploaded after a 20 s pause, at least every 2 minutes while changes keep coming, one upload at a time, at once when the tab is hidden. The local recovery copy is kept as before.
- Settings per device (Drive menu, Search; manual, no automatic sync): Save This Device's Settings asks for a name for the device (first guessed, e.g. "Windows app", "Chrome on Android"; kept with a fixed id in localStorage `vormcraft.device`) and writes its preferences into `VormCraft settings.json` in the VormCraft folder (`{format: 'vormcraft-settings', version: 1, devices: {id: {name, saved, app, settings}}}`); other devices' entries are kept. Load Settings lists the saved devices (this one first) to Load onto this device (to set up a new computer like another) or Delete (asks first). Loading sets every synced preference (resetting those the saved set lacks) and offers to restart (after the unsaved-changes question) so they all take effect.
- What travels is listed in `src/app/preferences.ts` (`PREFERENCES`): sky and ground, Settings (except the backup folder), default units, the tool palette (order, chosen tools, side) and top bar, export, import and 3D Text choices. Device-only: Drive sign-in and autosave, window positions, the palette tucked away, Viewer mode resolution, tips, caches. A test fails if a new `vormcraft.*` key is not listed.
- The Drive button shows unless switched off in Settings → Google Drive (localStorage `vormcraft.drive.hidden` = "1"); a change takes effect at once. Google verified the app (brand verification, November 2026), so `DRIVE_IN_TESTING` in `src/app/drive/preview.ts` is false; set to true (only if the app ever goes back into testing), Connect first says that only accounts on the test list can sign in and that it opens to everyone once Google has verified VormCraft, and a refused sign-in says the same. The web sign-in token lasts an hour; renewing it needs a click (browsers block pop-ups otherwise), so the status bar asks for it.
- Windows app: Google's installed-app flow. `src-tauri/src/google.rs` opens Google's sign-in page in the person's browser and waits (up to 5 minutes) for Google's answer on a one-off loopback address (http://127.0.0.1:<random port>); `desktopAuth.ts` makes the PKCE codes, swaps the answer for tokens at oauth2.googleapis.com (allowed in the CSP, with www.googleapis.com for Drive) and keeps the refresh token in Windows Credential Manager (`keyring`, entry "VormCraft" / "google-drive"), so the sign-in lasts between sessions and tokens renew without asking. Disconnect revokes it and deletes the entry.
- The desktop client's ID and secret are built in by `src-tauri/build.rs`: from the `GOOGLE_DESKTOP_CLIENT_JSON` GitHub secret in release builds, else from `~/.vormcraft/google-desktop-client.json`. Never commit that file. Without either, the Windows app is built without Drive.
### Web version
- The same app, built from the same tag, published on GitHub Pages after the Windows release. Installable (manifest, icons, own window with no browser bars); works offline: a service worker (generated by `scripts/offline.ts`) stores every file of the build and serves it (ignoring Vary, so module scripts match). A new version downloads in the background; the app shows its notes (`version.json`) and asks before switching. Desktop Chrome/Edge open .vorm files through `launchQueue`.
- Web differences: Save downloads the file; autosave copies live in IndexedDB (persistent storage requested); the browser chooses the graphics card. Same version number and file format as the desktop app.
- Layout (kept on the device in localStorage): tools in the palette can be dragged to new places (dropped before or after the tool under the cursor; a drag is not a click; Esc cancels; `vormcraft.palette.order`, pure helpers in `src/app/toolOrder.ts`, tools added later go at the end). Tools can be left out of the palette: right-click a tool → Remove … from Palette, or Customise Tools… (right-click the palette, Search) for a tick box per tool with presets (Essentials, All tools); Select always stays. Left-out tools still work from their keys and Search, and are listed under the ⋯ More tools button at the end of the palette (click one to use it; Add to Palette, Customise Tools…). Kept as `vormcraft.palette.tools` (`hidden`, `known`, `unseen`; pure helpers in `toolOrder.ts`). Tools from a newer version join the palette when nothing was ever left out; otherwise they stay out, the ⋯ button shows a dot and lists them as new until it is opened, and a notice says what is new. Right-clicking the palette also offers: Move Tools to the Right/Left (`vormcraft.palette.side`; on the right it sits between the view and the side panels), Reset Tool Order, Hide Tools, Hide/Show Top Bar (also in Search). The top bar's last button (up arrows) hides it, leaving a thin strip whose tab brings it back (`vormcraft.toolbar.hidden`). The top bar starts with the logo and the design's name (• while it has unsaved changes); Viewer mode is the blue eye button after it.
- Smaller screens: the toolbar wraps, side panels float over the view below 900 px wide, smaller buttons below 520 px.
### 3D Text
- The 3D Text tool (palette, Search) asks for the text (several lines allowed), a font from the computer's own (Arial, Verdana, Georgia, Times New Roman, Courier New, Impact…), bold, italic, the letter height (of a capital H), how far to push the letters out (0 leaves flat faces) and whether they stand up facing the front or lie flat; the choices are remembered. The text is drawn large on a canvas, its outline traced (`src/core/ops/text3d.ts`: marching squares with crossings placed between pixels, Douglas–Peucker smoothing, outlines sorted into letters and holes by nesting, overlapping letters merge), made into faces and pushed out into closed solids, with the seams round curves softened. It is then placed like a Library item (outline follows the cursor, arrow keys turn it) as one unpainted group named after the text.
### Text labels
- Labels are erased like anything else: a label placed or clicked with the Text tool is selected, so Delete erases it; the Eraser erases a clicked label; box selection takes labels whose text lies in the box; right-clicking a label selects it and opens the menu (Erase).
- Dragging a label's text moves it (on a plane through it facing the viewer); double-clicking it asks for new text. Each is one undo step.
### Dimensions
- The Dimension tool (palette, Search; no key) measures a line end to end: click a line (or two points), move out from it and click, or type how far out and press Enter. It is placed selected.
- Drawn as faded dashed extension lines from a small gap off both ends of the line to a little past the dimension line, and a faded dashed dimension line with an arrow at each end pointing out to the extension lines, so it is clear the value runs from end to end. The value sits in the middle, in the design's units.
- Dragging the value moves the dimension out from the line (it stays parallel to and centred on what it measures; `dimensionDragPoint`, `dimensionLayout` in `src/tools/dimension.ts`). Double-clicking it asks for text to show, starting from the measured length; empty text or the measured length shows the measured length again (and follows the units).
- A dimension is a label with an `end` (`Label` in `src/doc/Labels.ts`): selected, erased, moved and copied with Move, saved (format 7) and undone like a label. It keeps its own ends: it does not follow the geometry if that is moved on its own.
### Units
- Each design has its units (`Document.units`, saved from format 7; older files open in millimetres): millimetres, centimetres, metres, inches, feet (decimal places 0–3, trailing zeros dropped), or feet and inches (to the nearest 1, 1/2 … 1/64 inch, as 3' 6 1/2"). The model is always in millimetres; units change only what lengths show as and what a number typed without a unit means (inches for feet and inches). Typed units still work, and so do fractions ('6 1/2"', "3/4").
- New asks for the units (starting from the last ones chosen on this device, `vormcraft.units.default`); the design started when the app opens uses those too. Design Properties (click the design's name, the units button by the Measurements box, or Search) changes them as one undo step; nothing changes size.
- `formatLength`, `formatLengths`, `formatArea` and `parseLength` (`src/tools/units.ts`) use the open design's units (set by the ToolController whenever the document changes) unless given others. Areas show in the unit squared (square feet for feet and inches; millimetres switch to square metres from 1 m²).
### Library
- Library panel (toolbar, Search "Library"): ready-made objects to place, made for VormCraft only (no outside models): built by our own code (`src/library`, pure TypeScript on the core, no DOM) at common real-world sizes in mm. Light and fast: plain colours, few faces (≤ 600 per item). Phase 1 is Household (Furniture, Kitchen, Bathroom, Electronics, Lighting, Decor; 49 items). Saving your own items ("My Library") comes later.
- An item (`LibraryItem`, `src/library/catalog.ts`): id, name, category and subcategory, rooms (an item can be in several), search tags (other names), optional sizes (variants; the first is the default), `hangs` (hangs from the point clicked: pendant and ceiling lights), and `build(variant)` returning its parts, one per paint. Items stand on z = 0 centred on the origin, front facing -Y; wall items (wall cabinets, mirrors, frames, clocks, hoods) are made at their usual height above the floor.
- Kit (`src/library/kit.ts`): boxes, prisms, true-circle cylinders and lathed shapes (Follow Me round a circle), joined by a Manifold union per part (shapes in a part overlap where they join) and cut (`cut*`). Paints: `PAINTS` (name and colour; glass is see-through).
- Search (`src/library/search.ts`): every searched word must match the name, tags, kind, rooms or size names (whole word, start of a word, or with a typo: 1 for 4–6 letters, 2 for 7+); plurals and accents ignored; name matches rank first; filters by room and kind. An empty search lists everything in catalogue order.
- Placing (`PlaceTool`, tool id `place`): the item's outline follows the cursor (its base centre, or top centre if it hangs, on the snapped point); arrow keys turn it 90°, a typed angle turns it exactly; a click adds it as one undo step ("Place Bed") as a group named after the item, with a group per part inside (named Frame, Mattress…, painted through the group so recolouring is easy); a one-part item is one group. Paints are matched with the document's materials by name and colour, else added. Then Select comes back with the new group selected. Esc cancels. The outline is drawn thin and dark (not in the selection blue).
- Panel: search box, room list, kind chips, a grid of cards (picture, name, size W × D × H, size list). Pictures are drawn on first sight by a small renderer of their own (`src/view/thumbnails.ts`), one at a time, and kept on the device (localStorage `vormcraft.library.thumb.<LIBRARY_VERSION>.<id>`; bump `LIBRARY_VERSION` when items change shape). The library code loads when the panel first opens (its own small chunk). Below 900 px wide the panel closes when an item is chosen.
### Import
- OBJ (text: v/f with v/vt/vn and negative indices; objects, else groups, become separate groups) and STL (binary or text, detected). Units chosen on import (mm, cm, m, in, ft; live size preview), Y-up or Z-up, remembered per format.
- Mesh to model (`src/core/ops/importMesh.ts`): corners welded; polygons with no area dropped; non-flat polygons fanned; neighbouring coplanar polygons with consistent winding merged into one face (outer loop + holes; if the outline is ambiguous the pieces are added singly); polygons that cannot join a valid 2-manifold (flipped, more than two faces on an edge) skipped and counted; collinear vertices removed; edges between faces under 20° softened (optional).
- Each object is added as a group in the current context (one undo step), selected and zoomed to. Files over 300,000 polygons ask first.
- SketchUp (.skp): read by OpenSKP (MIT, pinned to 1.4.0, reviewed; read in a Web Worker, `src/app/skpWorker.ts`), converted by `src/io/skpImport.ts`. The file becomes one group; each placed group/component becomes a nested group with its transform baked in (13-number placement: row-major 3×3, translation, overall scale; inches → mm). Faces keep loops/holes and paint (front, else back); soft/smooth/hidden edges are soft; arcs become true curves where the placement keeps them circles; mirrored placements reverse loops. A face that clashes with its neighbours is turned round, else given vertices of its own, else skipped; counts are reported. Materials (colour, opacity, textures sized from inches, images shrunk to 1024 px), group paint, hidden placements, scenes (camera only) and root guides come in; layers/tags, texts, dimensions, section planes and positioned texture mapping do not. A file with no placed geometry says so; over 300,000 placed faces warns first.

## Build Phases
- **Phase 1: Geometry Core (no graphics)** — Half-edge model, faces with holes, face splitting, extrude, flush push-through, Manifold boolean subtraction, watertight check. Example tests: a rectangle extruded to a box gives 6 faces; a circle pushed flush through a box gives a through-hole and a watertight solid; an angled cut-through gives a watertight solid.
- **Phase 2: Display and Picking** — Three.js scene, orbit, pan and zoom, triangulation with face IDs, hover highlighting.
- **Phase 3: Tools** — Add Select, Rectangle, Push/Pull, Circle, Guides and Offset one at a time, each with typed input and tests. Then add inference snapping.
- **Phase 4: Export and App** — STL and OBJ export, save and open in our own file format, undo and redo, Tauri desktop build.
